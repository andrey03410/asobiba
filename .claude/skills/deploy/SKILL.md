# Деплой asobiba

Релиз определяется коммитом `main`, фактически запущенным на VPS. Workflow `production.yml` проверяет контейнер и публикует его в GHCR по полному SHA. В Asobiba workflow закрепляет коммит соседнего Douga в шаге checkout.

1. Сверь SHA с задачей `/feature` и проверь состояние workflow. Если `AUTO_DEPLOY` выключен, запусти `gh workflow run production.yml --ref main` и сверь SHA в запущенном `Production`.
2. Дождись результата job `deploy` через `gh run watch <id> --exit-status`. Успешный job `image` подтверждает только сборку. При сбое проверь статус запущенного образа до повторной попытки.
3. Открой HTTPS на порту `8445` удалённого хоста из переменной `DEPLOY_HOST`. Проверь сайт, WebSocket и доступность Douga в общей сети; проверь импорт снимка при наличии проверочного проекта. Зафиксируй SHA, ссылку на запуск и результат проверки.
4. Для отката выбери предыдущий проверенный SHA и выполни `bash release.sh asobiba <sha>` из каталога развёртывания на VPS с доступом к GHCR. Сценарий сохраняет копию SQLite перед стартом. Если схема несовместима, отдельно проверь состояние базы перед восстановлением.

Рабочие env и ключи находятся на VPS и в GitHub Actions Secrets. Проверочные аккаунты и результаты с персональными данными находятся в `storage/verification/`.
