# verify — QG и проверка вживую

## Порядок

1. **Зоны.** Собери изменённые файлы вместе с незакоммиченными:
   `git diff --name-only main` и `git ls-files --others --exclude-standard`.
   Сопоставь их с карточками [`.ai/map/`](../../../.ai/map/). Что проверять вживую,
   написано в разделе «Как проверить» каждой карточки.
   Если изменены только доки (`*.md`, `.ai/`), тройка не нужна: достаточно проверить
   ссылки и пути, затем перейти к шагу 4.
2. **Тройка** после последних правок, строго в этом порядке:
   - `npm test`. Запиши число тестов и файлов. Тесты работают со своей базой
     `storage/test/test.db` и не трогают базу разработки.
   - `npm run build` — сборка сайта в `apps/web/dist`. Dev-серверу она не мешает.
   - `npx tsc --noEmit` — типы всех пакетов одним проектом.
3. **Живые проверки** по зонам:

   | Что затронуто | Как проверить |
   |---|---|
   | Сайт и UI | `npm run dev` (порты 8787 и 5173 проверить заранее), браузер на `http://localhost:5173`: встроенный браузер или Chrome. Скриншоты в `storage/verification/<задача>/` |
   | API и вход | HTTP-пробы с куки-сессией, см. «HTTP-пробы» |
   | Партия, комнаты, WebSocket | `node scripts/verify-game.mjs` — два игрока по WebSocket доигрывают партию до победы |
   | SDK и игры | юниты пакета плюс `config_simulate` и `config_preview` через MCP-драйвер |
   | MCP | `node scripts/verify-mcp.mjs` — настоящий Streamable HTTP клиент по токену проходит сценарий агента, см. [mcp.md](../../../.ai/map/mcp.md) |
   | Картинки | MCP-драйвер: SVG → PNG, импорт по ссылке, загрузка файла по одноразовой ссылке; PNG открывается и совпадает по размерам |
   | Только доки и конфиги | достаточно проверить, что ссылки и пути живые |

4. **Запись.** В `verify.md` задачи укажи команды и цифры, что смотрел глазами
   и пути к доказательствам. Доказательства клади в `storage/verification/<задача>/`: в git они не попадают.
5. **Честно.** Красный результат показывай с выводом. Готовность по типам и юнитам не
   объявляй. Пропущенную проверку называй пропущенной и объясняй почему.

Ниже — рецепты. Ищи нужную зону по заголовку.

## Запуск

```bash
lsof -nP -iTCP:8787 -sTCP:LISTEN; lsof -nP -iTCP:5173 -sTCP:LISTEN   # порты свободны?
npm run dev        # сервер :8787 + сайт :5173
```

Если порт занят сервером владельца, пользуйся им, а не поднимай второй.
После правки `apps/server/prisma/schema.prisma`: `npm run db:migrate -- --name <что>`
и перезапуск `npm run dev` — работающий процесс держит старый Prisma-клиент.

## Проверочный аккаунт и токен

```bash
node scripts/seed-verify.mjs   # создаёт verify-a и verify-b, печатает путь к storage/verify/accounts.json
```

Логины, пароли и MCP-токен лежат в `storage/verify/accounts.json`. В чат и в git их не выводить.

## HTTP-пробы

Логин — `POST /api/auth/login {login,password}`, сессия в куке `asobiba_session`.
Дальше обычные `fetch` с этой кукой. Образец — `scripts/verify-game.mjs`.

## Драйв UI

Встроенный браузер Claude: `preview_start` с именем `asobiba-dev` из `.claude/launch.json`,
затем `read_page`, `find`, `computer`. Для двух игроков — две вкладки: вторую логинь
под `verify-b` через `javascript_tool` (`fetch('/api/auth/login', …)` и перезагрузка) или
используй драйвер WebSocket для второго игрока.
