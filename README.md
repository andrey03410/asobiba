# Asobiba 遊び場

Сайт мини-игр для своих. Новые игры добавляет разработчик, а игроки и их ИИ-агенты
настраивают существующие: правила, режимы, раунды, таймеры, визуал. Главный сценарий —
человек пишет агенту, какую игру хочет, агент через MCP собирает конфиг из возможностей
SDK, проверяет его, смотрит превью и создаёт лобби. Друзья заходят по ссылке и играют.

На сайте две игры: гибкие крестики-нолики и **Jinchi** — захват территории
прямоугольниками по броску двух кубиков. В Jinchi есть шесть карт, редактор стен
и стартовых зон с симметрией, карты до 200×200, полный экран и миникарта.

## Быстрый старт

Нужен Node 22.12+.

```bash
npm install
cp .env.example .env
npm run invite          # первое приглашение всегда админское: откройте ссылку и зарегистрируйтесь
npm run dev             # сервер :8787 + сайт http://localhost:5173
```

База SQLite создаётся миграциями в `storage/asobiba.db`, картинки лежат в `storage/assets/`.

## Подключить агента

В кабинете сайта («Агент (MCP)») создайте личный токен — там же будет готовая команда:

```bash
claude mcp add --transport http asobiba http://localhost:5173/mcp --header "Authorization: Bearer asb_…"
```

Дальше просто попросите агента: «создай лобби крестиков-ноликов 7×7 на троих, четыре в ряд, смешной визуал».

## Продакшен на небольшом сервере

```bash
npm ci
npm run build           # сайт в apps/web/dist
PUBLIC_URL=https://games.example.com COOKIE_SECURE=1 HOST=127.0.0.1 npm start
```

Один процесс на `:8787` отдаёт сайт, API, WebSocket и MCP. Перед ним — Caddy или nginx
с HTTPS и проксированием WebSocket. `npm start` сам применяет миграции.

### Видео-игры и douga

Видео-квизы играют сцены роликов [douga](../douga): пакеты `@douga/*` подключаются из соседней
папки `../douga/packages`, поэтому douga кладётся рядом и ставится первой (`npm install` в ней).
Ролик импортируется по токену из douga (`DOUGA_URL`) и дальше живёт в пуле asobiba: партии идут,
даже когда douga выключена. На одном сервере — две папки рядом, два имени за одним прокси:

```caddy
games.example.com { reverse_proxy 127.0.0.1:8787 }
douga.example.com { reverse_proxy 127.0.0.1:3000 }
```

`DOUGA_URL=http://127.0.0.1:3000` — внутренний адрес douga. Пример выкладки обоих —
[`scripts/deploy.sh`](scripts/deploy.sh).

## Устройство

| Папка | Что там |
|---|---|
| `packages/sdk` | SDK игр: схема конфига, проверка, движок партии, прогоны, возможности для агента |
| `packages/api` | Типы HTTP и WebSocket между сервером и сайтом |
| `games/jinchi` | Захват территории: движок, карты, редактор, доска и навигация |
| `games/tic-tac-toe` | Игра: правила, визуал, пресеты и SVG-рендерер |
| `apps/server` | Fastify: вход, картинки, конфиги, лобби, комнаты, MCP |
| `apps/web` | Сайт на Vite и React |

Команды, карта кода и правила для агентов — в [`AGENTS.md`](AGENTS.md).
Проверки: `npm test` → `npm run build` → `npx tsc --noEmit`.
