# Сайт

Одностраничное приложение `apps/web` на Vite и React 19. Через него люди входят по
приглашению, собирают конфиг из пресета или своего сохранённого конфига, создают лобби,
играют вживую и ведут кабинет: токены для агента, медиафайлы, конфиги, приглашения.
Проверка и превью конфига работают прямо в браузере на том же SDK, что и сервер.

## Где код

- [`apps/web/src/App.tsx`](../../apps/web/src/App.tsx) — маршруты: `/login` (`?next=`), `/register?invite=`, `/`, `/new` (`?game=&preset=` или `?config=`), `/lobby/:id`, `/account` (`?tab=assets|configs|invites`), 404.
- [`api.ts`](../../apps/web/src/api.ts) — `fetch` к `/api` с типами из [`packages/api`](../../packages/api/src/index.ts), `ApiRequestError` с `issues`. На 401 вне `/api/auth/*` и `/api/me` сессия считается истёкшей.
- [`auth.tsx`](../../apps/web/src/auth.tsx) — контекст личности (`/api/me`), защита аккаунта через `RequireAuth accountOnly`, синхронизация вкладок и возврат к последней ссылке лобби.
- [`pages/LobbyEntryPage.tsx`](../../apps/web/src/pages/LobbyEntryPage.tsx) — публичный вход по `/lobby/:id`: приглашение без сессии или существующий `LobbyPage` для аккаунта/гостя.
- [`components/LobbyInvitation.tsx`](../../apps/web/src/components/LobbyInvitation.tsx) — краткая карточка, имя и одно действие вступления/наблюдения; [`SessionActions.tsx`](../../apps/web/src/components/SessionActions.tsx) — выход и переход в аккаунт, в том числе в шторке сцены.
- [`useLobbySocket.ts`](../../apps/web/src/useLobbySocket.ts) — WebSocket `/ws`: подписка на лобби, вид партии, переподключение с растущей паузой, `ping` раз в 20 с и оценка смещения часов сервера.
- [`games.ts`](../../apps/web/src/games.ts) — каталог игр для проверки в браузере и React-клиенты (`Board`, `SeatIcon`, `css`).
- [`jsonSchema.ts`](../../apps/web/src/jsonSchema.ts) и [`components/SchemaForm.tsx`](../../apps/web/src/components/SchemaForm.tsx) — форма по JSON Schema из `game_capabilities`: поля, вложенные разделы, чекбоксы для массивов enum, выбор цвета, ошибки по `path`.
- [`components/ConfigPreview.tsx`](../../apps/web/src/components/ConfigPreview.tsx) — превью «Начало/Конец» через `client.previewMatch`.
- [`components/MatchHud.tsx`](../../apps/web/src/components/MatchHud.tsx) — раунд, счёт, чей ход, таймер, баннеры раунда и итога.
- [`pages/`](../../apps/web/src/pages/) — `NewLobbyPage` (основа, форма или JSON целиком, превью, создание), `LobbyPage` (места, старт, «Сыграть ещё», доска), `account/*Tab.tsx`.
- [`styles.css`](../../apps/web/src/styles.css) — свои стили без UI-библиотек, светлая и тёмная тема по `prefers-color-scheme`.
- [`vite.config.ts`](../../apps/web/vite.config.ts) — `127.0.0.1:5173`, `strictPort`, прокси `/api`, `/files`, `/mcp`, `/ws` на `127.0.0.1:8787`.

## Как устроено

- **Приглашение.** Без сессии `/lobby/:id` получает краткий публичный DTO и предлагает имя + «Присоединиться». Одно действие создаёт гостя и сажает игроком. При полном/идущем лобби — «Смотреть»; закрытое/несуществующее лобби не запрашивает имя. `attempt` — общий секрет незавершённого входа между вкладками: Web Lock + localStorage, без Web Locks — атомарная транзакция IndexedDB (`guestIdentity.ts`). После известного успешного входа ключ удаляется; при потерянном ответе без куки сохраняется для повтора. Перед гостевым запросом личность перечитывается через `/api/me`. Ошибка сохраняет имя; при уже созданной сессии клиент обновляет `/api/me` и предлагает обычные действия лобби.
- **Личности.** Действующий аккаунт или гость открывает лобби без представления. У гостя нет общего списка, создания и кабинета; закрытые разделы предлагают вход с возвратом к приглашению. Гостевая сессия живёт 30 дней; имя не восстанавливает место без куки. Одна куки — одна личность и одно место во всех её вкладках. `localStorage` передаёт только сигнал смены входа; вкладки перечитывают `/api/me`, дополнительно — при фокусе и 4401. `LobbyPage` перемонтируется по ID личности, очищая прежнюю доску и сокет.
- **Смена входа.** «Выйти»/«Войти в аккаунт» используют общие `SessionActions` в шапке и гостевой шторке. Ошибка сервера сохраняет текущую сессию в UI. Активная гостевая партия требует подтверждения; после выхода место не переходит в аккаунт. На `/login` гость сначала завершает сессию, затем вводит пароль. `safeNext` разрешает только внутренний адрес.
- **Создание лобби.** Основа — пресет игры или свой конфиг. Документ правится формой или как JSON. `validateConfig` из SDK работает на каждый ввод (через `useDeferredValue`), ошибки встают у полей, превью держит последний верный вариант. Сервер проверяет заново, включая владение картинками, и его `issues` показываются отдельным списком. Неизменённый сохранённый конфиг уходит как `configId`, изменённый — как документ или новым сохранением с галочкой.
- **Лобби.** Страница подписывается на `/ws` до того, как человек сел: смотреть может любой вошедший. Место игрока берётся только из сообщений `match`. Хозяин видит «Начать» (после партии — «Сыграть ещё») и «Закрыть лобби», игрок — «Выйти» (во время партии неактивна).
- **Сцена партии** — [`components/MatchStage.tsx`](../../apps/web/src/components/MatchStage.tsx). Как только лобби в `playing`, страница лобби рисует только сцену: фиксированный слой во весь экран, сверху тонкая панель (кнопка «Лобби», название, раунд серии, чей ход, таймер, счёт серии, полный экран), под ней доска с `stage` и `fullscreen`. Лобби (участники, ссылка, конфиг) открывается шторкой справа, Esc закрывает. После итога — карточка «Сыграть ещё» (хозяину), «В лобби», «Посмотреть доску». «В лобби» возвращает обычную страницу до следующего старта. Полноэкранный режим — Fullscreen API на элементе сцены. Пока сцена открыта, у `body` класс `has-stage` и нет прокрутки.
- **Таймер.** Дедлайн приходит в часах сервера. Клиент добавляет смещение (`serverTime` минус локальное время) и не показывает больше `turnSeconds` из конфига: смещение — оценка.
- **Итоги раунда.** Игра отдаёт причину без номера места (`summary`: «собрана линия»), имена победителей HUD подставляет сам.
- **Подписи мест.** `LobbyDto.seatNames` — снимок имён текущей/последней партии; используется как fallback после выхода участника. Гостевые подписи включают номер, поэтому одинаковые имена различимы на доске и в составе.
- **Кабинет.** Токен показывается один раз вместе с командой `claude mcp add …` и блоком `.mcp.json` от `PUBLIC_URL`. Картинки загружаются сырым телом `POST /api/assets?name=`, можно перетащить сразу несколько. Приглашения видны только админу.
- **Новая игра на сайте** — строка в `games.ts`. Без клиента сайт не рисует игру и не проверяет её конфиг, это делает только сервер при создании.
- **Русское поле.** Доска — HTML: барабан, табло, клавиатура, кроссворд суперигры. Превью в лобби рисуется из уже отданного конфига, поэтому свои ответы там заменены. Живые буквы приходят только в виде партии.

## Quizor

- `/new?game=quizor`: выбор пресета/сохранённого квиза и сводка `QuizSummary`.
  Редактора вопросов на сайте нет, их собирает агент. В лобби показываются название,
  число вопросов и форматы раундов; превью сводки не запускает движок со скрытыми правилами.
- Хозяин назначает ведущего из зрителей до старта. Выбрав себя, сначала переходит
  в зрители; обычный игрок тоже может перейти в зрители вне партии. Для required
  кнопка старта ждёт ведущего. Ведущий не имеет игрового места.
- `useLobbySocket` отдельно отправляет `action` и `control`; `controlRole` приходит
  от сервера. MatchStage передаёт onControl/controlRole доске. Локальные значения
  роли не заменяют серверную проверку прав.
- Доска занимает всё пространство сцены, прокручивает только внутреннюю область.
  Полоса счёта снизу остаётся видимой; на узком экране своё место закреплено первым.
  Формы порядка имеют кнопки вверх/вниз, соответствие — select, точка — касание
  или координаты; числовой ввод принимает запятую.
- Пауза закрывает вопрос заставкой и останавливает медиа. Черновик остаётся в состоянии
  доски и на сервере; возобновление показывает 3–2–1. Ready содержит ожидаемые
  phase/questionId: запоздавшая готовность буфера не двигает следующий вопрос.
  После продолжения и reconnect клиент синхронизирует видимый черновик ещё раз;
  ответ и черновик привязаны к questionId, пауза до истечения debounce не теряет ввод.
- Синхронизация медиа — серверные времена блока и clip from/to/speed/repeat;
  если autoplay запрещён, появляется кнопка запуска. Звук выключен до жеста,
  compact/mute — предпочтения этого устройства. В «Файлах» кабинета доступны аудио
  и видео с native controls, прежняя загрузка картинок сохранена.
- Проверка: `node scripts/verify-quizor.mjs`, затем browser-lobby из
  `storage/verification/06-quizor/browser-lobby.json`; desktop, 390×844, fullscreen,
  pause/draft/reveal, реальное воспроизведение WAV/MP4. PNG и снимки — рядом.

## Jinchi

- В форме `rules.map` заменяется `MapEditor` через `SchemaForm.overrides` по пути.
  Остальные поля остаются схемой. Не создавай новую копию map на каждый render:
  ссылка родительского значения нужна для истории пользовательского жеста.
- `SchemaForm` поддерживает `enumNames` (подписи по индексу enum), машинные значения
  сохраняются. В Jinchi скрыты технические ключи, человеческие названия из meta.title.
- Начальное превью Jinchi — старт: рисование большой карты не запускает симуляцию
  после каждого движения кисти. Конец пользователь запрашивает отдельно.
- Доска получает имена игроков и clockOffset. Внутри fullscreen остаются счёт клеток,
  кубики, таймер, правила и события. R/правый клик — поворот, H — подсказки,
  на телефоне тап выбирает фигуру, кнопка подтверждает; drag ход не отправляет.
- Ожидание подтверждения ручного броска учитывает dice (turnId не меняется), при
  потерянном соединении кнопки доступны для повтора через 3,5 с.

## Грабли

- Начальный HTTP-снимок лобби заполняет только пустое состояние. Более новый WS push или ответ команды имеет приоритет; поздний GET не должен вернуть идущую партию в waiting. WS-снимок принимается только для текущего id маршрута.

- Итог «Ничья» и «Победителя нет» — разные вещи. SDK пишет `draw: true`, когда победителей не ровно один, поэтому сцена смотрит на `lastRound.draw`: соло, проигравший суперигру, получает «Победителя нет».
- Куки привязаны к хосту, а не к порту: `localhost:5173` и `127.0.0.1:5173` — разные сессии. Этим удобно играть за двоих в одном браузере.
- В фоновой вкладке браузер ставит CSS-анимации на паузу: новые фигуры видны точками, пока вкладку не покажут. Это не баг рендерера.
- `PUBLIC_URL` в разработке — адрес Vite (`:5173`), иначе ссылки на лобби и адрес MCP поведут мимо прокси.
- `npm run build` пишет в `apps/web/dist`, который в продакшене отдаёт сервер. Без сборки `npm start` даёт только API.

## Как проверить

- `npm run build` — сайт собирается, `npx tsc --noEmit` — типы.
- Вживую: `npm run dev`, браузер на `http://localhost:5173`. Сценарий — регистрация по `npm run invite`, создание лобби из пресета с правкой формы, вторая сессия на `127.0.0.1:5173` под `verify-b`, партия до итога серии, «Сыграть ещё», кабинет. Рецепт входа и пароли — в скилле `verify`.
- Гостевой путь: открыть ссылку на другом хосте без сессии → имя → вступление → refresh → партия → «Лобби» → выход/вход в аккаунт. Во второй вкладке смена личности должна сбросить старый вид. Отдельно проверить полное, начавшееся и закрытое приглашение.
