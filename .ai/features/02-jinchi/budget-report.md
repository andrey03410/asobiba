# Бюджет случайной симуляции

Добавлен необязательный `GameDefinition.simulationBudget(rules)` с
`maxTotalActions` на весь вызов симулятора. Для Jinchi бюджет равен
`max(200, floor(20_000_000 / (width * height)))`; на 200×200 это 500 шагов.
`SimulateOptions.maxTotalActions` может уменьшить бюджет игры, но не увеличить.
Конечные лимиты округляются вниз и ограничиваются минимумом 1; отсутствие,
Infinity и NaN не вводят дополнительный лимит. Прежние игры без hook сохраняют
прежнее число прогонов. Единица — прежний шаг симулятора: ход или realtime tick.

`SimulationReport.rounds` теперь считает начатые прогоны, включая частичный;
`requestedRounds` — нормализованное число запрошенных прогонов (1–500),
`skippedRounds` — не начатые прогоны. Всегда `finished + unfinished == rounds`.
Среднее действий считается по начатым прогонам. Новый `budget-exceeded` означает
обрыв частичного прогона или отказ запускать оставшиеся прогоны из-за общего cap.
Он не создаёт ложный `never-ends` для частичного прогона. Собственный лимит
`maxActions` по-прежнему создаёт `never-ends`; при точном совпадении двух лимитов
сначала учитывается самостоятельный предел раунда, затем отказ от будущих прогонов.

Исправлена прежняя ошибка последнего действия: итог проверяется до обоих лимитов,
поэтому победа на последнем разрешённом ходу засчитывается завершённым прогоном.
Это работает и для пошаговых игр, и для realtime tick.

## Дополнение R3: бюджет времени

Ревью обнаружило, что один внешний ход Jinchi может обработать сотни внутренних
автобросков, поэтому одного числа действий недостаточно. Hook расширен до
`{ maxTotalActions, maxDurationMs? }`; Jinchi задаёт общий лимит **1000 мс**.
`SimulateOptions.maxDurationMs` может только уменьшить лимит игры. Время измеряется
монотонным `performance.now()`; `nowMs?: () => number` — только тестовый override
в аргументах функции, в конфиг игры он не попадает.

Дедлайн проверяется до нового setup, после setup, до следующего хода, после
вычисления legalActions перед apply/pass, а также перед отдельными realtime
действиями и tick. Итог состояния проверяется первым: терминальный setup или
последний завершивший раунд ход засчитывается, даже если сам пересёк дедлайн.
Дорогой незавершивший ход оставляет частичный прогон. Если время вышло до первого
setup, `rounds=0`, `skippedRounds=requestedRounds`, `averageActions=0`.
Сообщение `budget-exceeded` различает время и число действий.

Это кооперативный лимит: уже запущенный синхронный setup/apply/tick прервать нельзя;
проверка после его возврата не допускает новых дорогих операций. Поэтому допустимо
превышение на длительность одной операции, а не повторение её для всех прогонов.

Проверка: семь новых сценариев увидены красными до правок, затем зелёными. Fake-clock
тесты покрывают дорогой setup, предел до первого setup и между раундами,
терминальный setup, дорогие partial/final действия, lower-only caller limit и
дорогой legalActions без последующего apply. Свежий весь SDK + Jinchi engine:
**76/76**, `npx tsc --noEmit` — код 0.

Реальная карта из R3 (200×200, почти все стены, 8 баз с одной пустой клеткой,
d20, ordered, skipRounds=0), запрос 10 прогонов: **1,037 с**, начат 1 прогон,
7 внешних действий, один частичный, 9 не начаты; единственное замечание —
`budget-exceeded` по времени, без ложного `never-ends`. Логи:
`storage/verification/02-jinchi/duration-{tests,types,performance}.log`.
