# Доска и навигация Jinchi

Реализована задача 2 плана. Файлы: `games/jinchi/src/client/Board.tsx`,
`MapViewport.tsx`, `css.ts`, `index.ts`, `Board.test.tsx`.

## Что сделано

- Общий `MapViewport` с точным основным интерфейсом плана. Для отмены кисти при начале
  pinch добавлен необязательный `onStrokeCancel`. Редактор получает тот же viewport.
- SVG-территории объединяются по цвету, соседние клетки строки — в один участок пути.
  Сетка — pattern, скрывается при масштабе меньше 6 пикселей на клетку.
- Масштаб к курсору, перенос мышью/пальцем, pinch, навигация стрелками/WASD, `+`/`−`,
  `0`, `M`, `L`, миникарта с рамкой и переносом камеры. Новые `cells` не сбрасывают камеру.
- `F` и кнопка включают полный экран; при недоступном Fullscreen API используется
  фиксированное окно. Escape снимает класс и вызывает `exitFullscreen`.
- В HUD имена, площадь и доля территории, выбывание, текущий игрок, круг, два кубика,
  правила по текущему конфигу и последние 24 события. Таймер принимает оставшееся время
  либо сам считает его с учётом `clockOffset` и серверного дедлайна; обновляется раз в 250 мс.
- Призрак проверяется тем же `placementError`, что движок. `R`/правый клик поворачивают,
  `H` переключает подсказки; допустимые якоря видны также на миникарте. На телефоне тап
  выбирает место, «Поставить» подтверждает. Перетаскивание не делает ход.
- Повторная отправка одного действия блокируется до обновления состояния. Ручной бросок
  снимает блокировку при изменении кубиков без смены номера хода. После отклонения сервером
  без обновления состояния блокировка снимается через 3,5 секунды.
- Последний ход выделен, захват анимируется восемью группами волны. Reduced motion отключает
  анимации. Захват и отрисовка территорий не создают DOM-узел на каждую клетку.
- `staticRender` возвращает только SVG. Размеры сохраняют пропорции карты. Номера баз
  нарисованы контурами: они остаются видны в серверном resvg без системных шрифтов.
- `jinchiClient`, детерминированные стартовое/игровое превью, значок места, экспорт редактора
  и объединение CSS доски/редактора.

## Проверки

TDD: сначала шесть падающих SSR-проверок при пустых компонентах. После реализации зелёные.
Затем отдельно red → green для пропорций превью, серверного смещения таймера и наличия
номеров баз в PNG без шрифтов.

Последний локальный прогон:

```text
npx vitest run --config storage/verification/02-jinchi/unit.vitest.config.ts games/jinchi/src/client/Board.test.tsx
1 файл, 9 тестов пройдено
npx tsc --noEmit
успех
```

Проверки охватывают чистый SVG, цвета стен и территории, компактность 200×200,
HUD/имена/кубики/таймер/правила/события, наблюдателя, значок места, общий viewport,
пропорции SVG и пиксели номера базы в реальном resvg.

Превью `storage/verification/02-jinchi/board-preview.{svg,png}` отрендерено настоящим resvg
с `font.loadSystemFonts=false`, PNG осмотрен: цифры 1/2 видны, сетка/цвета корректны.
Рендер SVG+PNG стартовой карты 16×16 занял около 21 мс в последнем прогоне.

У этого исполнителя CUA не обнаружил доступного браузера. Основной исполнитель прошёл
живые редактор, zoom, fullscreen и партию; снимки лежат в
`storage/verification/02-jinchi/game-{desktop,mobile}.png`.
Для отдельных проверок ручного броска, отклонения действий и обновления камеры оставлен
неотслеживаемый harness `storage/verification/02-jinchi/board-harness.html` через Vite
`/@fs/Users/gel/my_projects/asobiba/storage/verification/02-jinchi/board-harness.html`;
`?size=200` включает большую карту. Он не меняет dev-конфигурацию и использует настоящий Match.

Общую тройку, полноценные жесты в браузере и итоговый QG выполняет основной исполнитель;
этот отчёт не объявляет всю задачу готовой по одним SSR/типам.
