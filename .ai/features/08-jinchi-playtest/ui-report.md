# Отчёт задачи 4: сцена и редактор Jinchi

16 ноября 2026. Исполнитель: jinchi_ui. Изменения не коммитились.

## Реализация

- Интерактивная карта и миникарта используют одну Canvas-текстуру: один пиксель
  на клетку, сглаживание выключено. SVG-превью для resvg сохранено.
- SVG-слой объектов группирует близкие цели с числом объектов; флаги и все пять
  спецклеток имеют отдельные векторные значки. Будущих исходов в UI нет.
- Подсказки ограничены 700 позициями; последний ход — 1000 поставленных и
  1500 захваченных клеток для анимации. Переход к последнему ходу не копирует
  весь массив большого окружения.
- Камера сохраняет логический центр и клеточный масштаб при resize/fullscreen;
  входящие данные не вызывают fit. Жесты отменяются при втором касании и resize.
  Тап при клетке мельче 12 CSS px сначала приближает область.
- Компактный счёт прокручивается одной строкой, скрытие убирает саму строку.
  Подробности, правила/легенда и события открываются поверх карты и не пропускают
  касания. В портрете управление внизу, при низком альбомном окне — справа.
- Скрытие счёта, миникарта и звук сохраняются на устройстве. Сигнал собственного
  хода одноразовый, 2,5 с, ключ round/turn/seat; dice и WS-дубликаты не меняют ключ.
  Фоновая вкладка получает сигнал только при возвращении. Таймер изолирован.
- Показаны разные кубики до d100, canRotate/canReroll/canSkip, заряды, текущая и
  следующая помеха. Итог включает клетки, флаги, эффекты и очки.
- MatchStage поддерживает information slot, GameClient.stageHud/resultSummary.
  Общая сцена сохраняет прежний HUD других игр; для Jinchi нет второго таймера.
- MapEditor принимает optional rules/onRulesChange/generator, сохраняет старый
  map-only контракт. Есть кисти флагов и эффектов, undo/redo объектов, явное
  подтверждение обрезки с числом потерянных баз/объектов. Ручной emit снимает
  метаданные баланса; обычная проверка запускается на границе жеста.
- Кисть копирует затронутые строки, flood использует typed queue, прямоугольник
  не создаёт миллион пар координат одним массивом. UI отвергает размер >1000.

## Дополнение: человеческая форма флагов и сюрпризов

После живой проверки root обнаружил, что обычная форма показывала служебные
имена и массивы координат. Добавлен `client/ObjectSettings.tsx` без изменения
NewLobbyPage и client/index.ts:

- `FlagSettings({ value: JinchiRules['flags'], onChange })`: человеческий выбор
  критерия; цена только для бонусного режима; цель только для главного режима;
  число флагов и объяснение кисти вместо редактирования координат. Выключение
  явно предупреждает об удалении размещённых флагов и очищает их/цель; цена
  сохраняется. Переход в бонусный режим сохраняет координаты и сбрасывает цель.
- `EffectSettings({ value: JinchiRules['effects'], onChange })`: число клеток,
  легенда, произвольный упорядоченный пул до 100 строк. Типы названы словами;
  веса 0–1000, бонус/штраф 1–100 000, индивидуальная нормализованная вероятность.
  Дубли строк не объединяются; изменение/удаление затрагивает только выбранную
  строку, остальные записи и координаты клеток сохраняются. Нулевая сумма
  объясняется без NaN; добавление сверх 100 заблокировано.
- `rules.ts`: только meta.title/description/enumNames полей flags/effects.
  Дефолты, ограничения и проверка правил сохранены.
- MapEditor при намеренном рисовании первого флага включает bonus и сохраняет
  настроенную цену. `rulesFromEditorMap` используется реальным emit; ссылка
  emitted.current совпадает с передаваемой rules.map, чтобы не сбрасывать undo.
- Стили новых компонентов добавлены в существующий JINCHI_EDITOR_CSS.

Root подключает exports и SchemaForm overrides `rules.flags`/`rules.effects`.
JSON-вкладка остаётся доступной. Browser Cua продолжает root.
