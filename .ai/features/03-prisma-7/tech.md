# Технические решения

## Исходная система

Проверено в коде и на копии проекта (см. [бриф](brief.md)):
- `apps/server/package.json` — `prisma` и `@prisma/client` 6.19.3; генератор `prisma-client-js`,
  `url = env("DATABASE_URL")` в [`schema.prisma`](../../../apps/server/prisma/schema.prisma).
- [`apps/server/src/db.ts`](../../../apps/server/src/db.ts) — `new PrismaClient({ datasourceUrl })`.
- Импорты типов `Prisma`, `User`, `Asset`, `GameConfig` из `@prisma/client` в четырёх сервисах.
- [`scripts/prisma.mjs`](../../../scripts/prisma.mjs) — обёртка CLI: грузит `.env`, по умолчанию
  абсолютный `DATABASE_URL`, передаёт `--schema`.
- Транзакции: пакетные `$transaction([...])` в `lobbies/service.ts` (5 мест) и одна интерактивная
  в `auth/service.ts` (регистрация), внутри неё только `tx`.
- База разработки `storage/asobiba.db`: даты Prisma 6 хранит в SQLite целыми миллисекундами.
- Карточки: [dev-env](../../map/dev-env.md), [server](../../map/server.md).

Prisma 7 по [гайду обновления](https://www.prisma.io/docs/orm/more/upgrade-guides/upgrading-versions/upgrading-to-prisma-7):
только ESM, генератор `prisma-client` с обязательным `output`, обязательный адаптер драйвера,
`url` в схеме запрещён (P1012) и переезжает в `prisma.config.ts`, `.env` сам не грузится,
`migrate dev` и `db push` не запускают `generate`.

## Решения

### T01. Версия

- Варианты: Prisma 8 (`8.0.0-rc.30`) · Prisma 7.10.1.
- Рекомендация: 7.10.1. Prisma 8 — кандидат и другая ORM; на SQLite нет `contract infer`,
  а даты из наших баз не читаются (`RUNTIME.DECODE_FAILED`), проверено на копии.
- **Решение:** `prisma`, `@prisma/client`, `@prisma/adapter-better-sqlite3`,
  `@prisma/driver-adapter-utils` — ровно `7.10.1`. Тег `latest` у `prisma` указывает на 8 RC,
  поэтому диапазоны (`^7`) не годятся.

### T02. Генератор и сгенерированный клиент

- Варианты: оставить `prisma-client-js` (устарел, будет удалён) · `prisma-client`.
- **Решение:** `prisma-client` с `output = "../src/generated/prisma"`, папка в `.gitignore`,
  генерация в `postinstall` (как и раньше). Импорты — из `../generated/prisma/client`.
  Расширения в импортах не нужны: сервер и скрипты запускает `tsx`, тесты — Vitest.

### T03. Конфиг CLI и адрес базы

- **Решение:** `prisma.config.ts` в корне: путь схемы, папка миграций, `datasource.url`.
  `scripts/prisma.mjs` остаётся точкой входа: грузит `.env`, подставляет абсолютный путь по
  умолчанию и запускает CLI из корня. Флаг `--schema` больше не нужен.

### T04. Формат дат

- Варианты: умолчание адаптера (ISO-строки) · `timestampFormat: "unixepoch-ms"`.
- Рекомендация: `unixepoch-ms`. При умолчании новые даты пишутся строками, старые остаются
  числами, и SQLite сравнивает любое число как меньшее любой строки: на копии базы все
  14 живых сессий стали «истёкшими».
- **Решение:** `unixepoch-ms` для всех клиентов, тест на формат хранения.

### T05. Одно соединение и транзакции

- Исходная проблема: адаптер держит одно соединение на процесс. Его мьютекс сериализует
  только транзакции между собой, а обычный запрос, пришедший во время открытой транзакции,
  выполняется внутри неё и откатывается вместе с ней. Воспроизведено тестом: запись
  параллельного запроса пропала при откате регистрации.
- Варианты: принять · держать транзакции короткими · обёртка над адаптером, которая ставит
  запросы вне транзакции в очередь, пока транзакция открыта.
- Рекомендация: обёртка. Она восстанавливает поведение Prisma 6 (запрос ждёт конца транзакции,
  а не попадает в неё) и не требует дисциплины в каждом месте кода.
- Риск: запрос через общий клиент изнутри интерактивной транзакции будет ждать её конца —
  до таймаута транзакции (5 с). В коде такого нет: в регистрации только `tx`. Правило
  записывается в карточку.
- **Решение:** `apps/server/src/sqlite.ts` — фабрика адаптера с асинхронным замком
  (FIFO) на `queryRaw`, `executeRaw`, `executeScript` и на всё время транзакции.
