## Уточнения

Перед брифом агент исследовал вопрос и пробовал переход на копиях (итог показан владельцу,
после чего пришло «да, переводи оба проекта»):
- Prisma 8 (самая новая) — кандидат `8.0.0-rc.30`, переписанная ORM с новым API запросов.
  SQLite в ней экспериментальный: `orm init` его не предлагает, `contract infer` не
  поддерживается, а даты из баз Prisma 6/7 (целые миллисекунды) не читаются —
  `RUNTIME.DECODE_FAILED`. Переход на 8 сейчас заблокирован.
- Prisma 7.10.1 — последняя стабильная, будет поддерживаться 18 месяцев после выхода 8.
  На копии Asobiba: тесты, сборка, живая партия и MCP зелёные, `npm audit` чистый.
  Ловушка: адаптер по умолчанию пишет даты ISO-строками, и сравнения со старыми
  числовыми датами ломаются (на копии все сессии считались истёкшими).
- Догадка агента: «самая последняя» для владельца — самая последняя, на которую можно
  перейти без блокеров, то есть 7.10.1; к 8 вернёмся, когда она выйдет и SQLite станет
  стабильным. Записано в «Хвосты» после вливания.

## Трек

`tech` — меняется инфраструктура доступа к базе, поведение сайта и MCP не меняется.

## Успех

- Сервер работает на `prisma`/`@prisma/client` 7.10.1 с адаптером SQLite, версии закреплены точно.
- Существующая база разработки открывается без миграций, даты остаются в прежнем формате
  (целые миллисекунды), сессии и сроки приглашений и билетов сравниваются верно.
- Тройка зелёная, живые проверки (сайт, партия по WebSocket, MCP) проходят.
- `npm audit --omit=dev` без находок про Prisma.
