# Yomifuda — продуктовые решения

Продукт принят владельцем 17 ноября 2026 года с уточнениями из [brief.md](brief.md).
Остальные решения агент принял в разрешённом автономном режиме. Реализация и
вливание разрешены после зелёных QG, живой проверки и свежего ревью.

## Цель

Карточная игра для компании: выбрать аниме-персонажа по знанию сюжета, не зная
чисел агента, затем вместе увидеть красивое раскрытие. Оценки честные «как есть»
по аниме: нет равного бюджета характеристик, нормализации по колоде или помощи слабым.
Одни персонажи объективно сильнее по сумме, другие слабее — это часть игры.

## Подход

Выбран отдельный движок игры Asobiba, общая арена и раскрытие через движок douga,
личная рука и доступное управление — React. Альтернативы: весь интерфейс в douga
сложнее для личных рук; заставка douga при обычной доске не даёт требуемого раскрытия.
Используем существующие пакеты и рендерер douga; конкретные контракты решаются в технике.

Списки читаются при подготовке, затем состав и оценки замораживаются.

## Сценарий

Агент получает возможности, собирает колоду и скрытые оценки, проверяет конфиг,
визуал и создаёт лобби. Трое входят по ссылке, получают по пять карт из колоды 60.
На экране всегда видны игроки, общий стол, номер раунда и активный показатель.
Игрок выбирает карту из своей руки и подтверждает. На столе появляется рубашка;
имя и оценка не раскрываются, пока все не сыграли. Douga одновременно открывает
персонажей, а затем анимирует значение активной характеристики и исход.
Раскрытие длится не менее настроенного времени, затем все подтверждают продолжение.
После каждого боя — случайный добор по одной, пока не опустеет колода; затем играем
остаток руки. В примере получается 20 боёв. Финал показывает общий счёт и победителя.

## Решения

### P01. Честные оценки и канон

- Варианты: Общая методика без выравнивания / максимум всех источников / равный бюджет.
- Рекомендация: Общая методика, наиболее сильная показанная версия в выбранных аниме и сезонах; без скрытых способностей из манги. Характеристика имеет публичное определение. Нет нормализации, лимита суммы и компенсаций.
- **Решение:** Владелец согласовал честные оценки и рекомендованный подход. Сильные во всём и слабые во всём персонажи допустимы.

### P02. Пул по профилям

- Варианты: 2 из 3 / все / другое условие пользователя.
- Рекомендация: По умолчанию 2 из 3; менять по запросу. Начатый просмотр: completed, watching, rewatching, on_hold, dropped, для незавершённого минимум один эпизод. Planned и избранное не обходят фильтр. Конкретные тайтлы/сезоны, без автоматического расширения франшизы.
- **Решение:** Владелец подтвердил 2 из 3 с настройкой; точные статусы приняты агентом автономно. Порог 2 допускает незнакомые третьему человеку аниме.

### P03. Тайна и douga

- Варианты: Общая douga-арена с личной рукой / всё в douga / только заставки.
- Рекомендация: Общая арена и раскрытие douga, личная рука и управление Asobiba. До раскрытия нет чужих карт и оценок ни в интерфейсе, ни в данных. После открывается только активная характеристика. Остальные значения скрыты до финала.
- **Решение:** Владелец согласовал. Агент-составитель знает оценки, но не печатает их пользователю; обычный просмотр библиотеки и лобби безопасный, полный авторский доступ отдельный и явный.

### P04. Победа при равенстве

- Варианты: Активная характеристика → сумма всех / сразу 0,5 / делить единицу.
- Рекомендация: Сначала максимальная активная оценка. Только среди разделивших её сравниваем сумму всех показателей. Единственный максимум суммы получает 1, при полном равенстве каждый оставшийся победитель получает 0,5, остальные 0. Число победителей не меняет 0,5.
- **Решение:** Прямое уточнение владельца. При 90/90/40 сравниваем сумму только первых двоих. Сумму остальных не показываем; при тай-брейке показываем сумму только его участников и причину результата.

### P05. Равные руки и вся колода

- Варианты: Размер кратен числу игроков / исключать остаток / неполные раунды.
- Рекомендация: Кратность обязательна; размер D, игроков N, рука H: D % N = 0 и H <= D / N. Игра требует ровно заданное число игроков. Добор случайный, без балансировки, все карты разыгрываются один раз.
- **Решение:** Владелец согласовал. Для 61 карты на троих предложить 60 или 63, не менять молча. 60/3/5 даёт 20 боёв, из них последние пять без добора.

### P06. Название

- Варианты: Yomifuda / Kagefuda / Chara Shōbu / Anime Kurabe / Fuda Clash.
- Рекомендация: Yomifuda, русское чтение Ёмифуда.
- **Решение:** Выбрано владельцем.

### P07. Отдельная игра

- Варианты: Отдельная игра / режим Quizor.
- Рекомендация: Отдельная игра со своими рукой, добором, сравнением и скрытым состоянием.
- **Решение:** Принято агентом автономно.

### P08. Игроки и состав

- Варианты: Настраиваемое число / строго трое.
- Рекомендация: 2–6 игроков, три по умолчанию. Фиксируем число мест при старте, новые люди только наблюдают. Число профилей подготовки независимо от числа мест.
- **Решение:** Числа настраиваются по брифу; предел 6 принят агентом для читаемой мобильной арены.

### P09. Набор характеристик

- Варианты: Свободный / фиксированные пять.
- Рекомендация: Один общий набор для всех карт. Обычно до шести; больше по явному запросу. Пример: сила, ловкость, музыка, харизма, красота. Система не запрещает седьмую.
- **Решение:** Подтверждено исходным брифом; минимально один показатель.

### P10. Шкала

- Варианты: Целые 0–100 / дробные / другая шкала.
- Рекомендация: Всегда целые значения; шкала по умолчанию 0–100, 0 и 100 допустимы, границы настраиваются. Значения всех карт полные и в диапазоне. Отсутствие знания не равно нулю: заменить сомнительного кандидата.
- **Решение:** Владелец отдельно подтвердил: характеристики всегда целые. Шкала и настраиваемость из брифа; замена неуверенных принята автономно.

### P11. Случайный показатель

- Варианты: Без немедленного повтора / независимый / мешок.
- Рекомендация: Равномерно без немедленного повтора, при одном показателе он повторяется. Режим повторов настраивается. Выбор не зависит от рук и счёта; следующий показатель узнаём в начале следующего боя.
- **Решение:** Принято агентом автономно в рамках «случайная новая характеристика».

### P12. Карта в руке

- Варианты: Имя, портрет, аниме, версия / один портрет / биография.
- Рекомендация: Имя, портрет, аниме, версия; никаких чисел, рангов, редкостей и подсказок силы. Увеличение карты по нажатию, выбор отдельным подтверждением.
- **Решение:** Без характеристик — требование владельца, поля и управление приняты автономно.

### P13. Объяснения и финальный разбор

- Варианты: Без объяснений / объяснение оценки / полный разбор сразу.
- Рекомендация: Объяснения не составляем и не показываем. В финале можно раскрыть все показатели сыгранной колоды по явному открытию разбора; до этого только уже открытые данные.
- **Решение:** Владелец прямо исключил объяснения. Финальный разбор принят автономно.

### P14. Повторы и разнообразие

- Варианты: Уникальные персонажи / дубли / квоты.
- Рекомендация: Один персонаж — одна карта, без дублей из-за имени, сезона или формы. Разнообразие по разрешённому пулу, без квот силы. Ограничение тайтлов — настройка подготовки, а не баланс.
- **Решение:** Принято автономно.

### P15. Недостаточный пул

- Варианты: Сообщить и предложить изменение / тихо расширить.
- Рекомендация: Сообщить нехватку без оценок; предложить уменьшить размер либо изменить фильтр. При недоступных списках не выдумывать просмотренное.
- **Решение:** Принято автономно.

### P16. Раздача

- Варианты: Честное перемешивание / равные по силе руки.
- Рекомендация: Серверная воспроизводимая случайность без подстройки силы, добора или будущего показателя. Сыгранное не возвращается.
- **Решение:** Следует брифу и принято автономно.

### P17. Таймер выбора

- Варианты: Без таймера / автокарта / пропуск.
- Рекомендация: Без таймера по умолчанию. Настраиваемое ограничение служит напоминанием: после истечения ждём человека, не ходим за него. Подтверждённый ход неизменен и содержит номер боя против запоздалого сообщения.
- **Решение:** Принято автономно; агент за людей не играет.

### P18. Темп раскрытия

- Варианты: Долгое раскрытие с готовностью / короткий автоматический переход.
- Рекомендация: По умолчанию 10 секунд: появление персонажей, анимация значений, время прочитать итог. Продолжение только после минимального времени и готовности всех. Время настраивается; reduced motion сохраняет время чтения. После раскрытия добор, затем новое сравнение.
- **Решение:** Долгое анимированное раскрытие — требование владельца; 10 секунд и готовность всех выбраны автономно.

### P19. Переподключение и выход

- Варианты: Восстановить своё место / перераздать.
- Рекомендация: Подтверждённая карта и своя рука сохраняются. Новый зритель не видит руки. Хозяин может остановить партию штатным закрытием лобби; автоматических ходов при обрыве нет.
- **Решение:** Принято автономно.

### P20. Изменения оценок

- Варианты: Заморожены / апелляция / новая оценка на ходу.
- Рекомендация: Оценки неизменны до конца; исправления только в новой версии колоды и новом лобби. Победу считает сервер без обращения к агенту.
- **Решение:** Принято автономно.

### P21. Безопасная сводка

- Варианты: Правила и числа / полный состав и оценки.
- Рекомендация: Размер, число игроков, показатели, правила тай-брейка, профили и условия отбора, без списка сильнейших и оценок. Автор может явно открыть полные данные для редактирования, обычный игрок не получает их автоматически.
- **Решение:** Принято автономно.

### P22. Внешние сервисы

- Варианты: Сохранённые данные / внешние запросы в бою.
- Рекомендация: Подготовка может использовать Shikimori и douga, партия живёт на сохранённых портретах и сценах/шаблонах. В бою не нужны агент и сервис douga.
- **Решение:** Принято автономно, соответствует существующей интеграции.

### P23. Телефон и полный экран

- Варианты: Один экран с игроками и столом / длинная страница.
- Рекомендация: Портретный телефон — основной сценарий. Игроки, их счёт, стол и рука видны одновременно; большая рука прокручивается внутри нижней зоны. Поддержать 360×640, 390×844, планшет и ПК, stage и fullscreen. Все поставленные карты до раскрытия рубашкой вверх.
- **Решение:** Прямое требование владельца; размеры проверки выбраны автономно. Красивую графику и анимации рисует douga, управление остаётся доступным без звука.

### P24. MCP, превью и живая проверка

- Варианты: Возможности → конфиг → проверка → превью → лобби / ИИ играет.
- Рекомендация: Агент получает полную схему, правила честной подготовки, профили и условия. Обычные ответы и превью не раскрывают реальные секреты. Проверить живую партию с несколькими игроками, тай-брейки, мобильный браузер и анимацию douga; доказательства в storage.
- **Решение:** Подготовка агентом и проверка вживую прямо запрошены владельцем. QG и свежее ревью обязательны до merge.

## Не входит

Коллекционная экономика, редкости, покупка и прокачка, эффекты и комбо, подстройка
силы персонажей, баланс рук, ИИ-судья в бою, онлайн-синхронизация аккаунтов Shikimori,
матчмейкинг, перераздача при выбывании и новые игроки посреди партии.

## Провал

Утечка оценок/чужой руки, подстройка силы, изменения оценок по ходу партии,
несыгранный остаток без согласования, нечитаемая мобильная арена, раскрытие до всех
ходов или слишком короткое для чтения, декоративная заставка вместо настоящей douga-графики.

## Уточнения финального ревью

Приняты автономно 17 ноября 2026 в рамках P05/P12. Один матч разыгрывает ровно одну
колоду, `series.rounds=1`: повторение после раскрытия оценок запрещено общей схемой.
Совместную победу получают все лидеры по очкам, включая полный паритет; имена всех
победителей сохраняются в общем результате. Очки боёв и счёт SDK-серии различаются.
Инспекция показывает полный портрет, имя, аниме и версию в прокручиваемом диалоге.
Закрытие или Escape не отправляет карту и сохраняет выбор; отправка отдельным подтверждением.
