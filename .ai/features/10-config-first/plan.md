# План реализации

Цель — конфиг как единственный обязательный вход для лобби, личная библиотека и справка для игроков. TypeScript, Fastify, Prisma, React, Vitest. [Продукт](product.md) · [Техника](tech.md)

## Ограничения

- Хранить входной JSON. Движок получает только результат серверной проверки.
- Личные записи и сохранение из лобби проверяют владельца, обычные ответы скрывают закрытые правила.
- На сайте один редактор JSON. Примеры и справка работают для всех пяти игр. Полноэкранная сцена остаётся доступной.
- Интеграционные запуски Vitest делят `storage/test`. Запускать их последовательно.

## 2. Справка из SDK

Файлы `packages/sdk/src/{game,capabilities,capabilities.test}.ts`, определения игр и HTTP-маршрут в `apps/server/src/routes.ts`. Сайт читает `GameGuide` из `GET /api/games/:id/guide` в ответе `{ guide }`. `GameGuide` содержит `id`, `title`, `info`, `tuning`, `promptExamples: string[]`, `exampleConfig: ConfigDocument | null`. `describeGameGuide(game)` экспортируется из SDK. HTTP-маршрут добавляется в задаче 1 после согласования сигнатуры.

## Фокус ревью

- Частичный документ, неизвестная игра и прежняя версия остаются доступны для правки, запуск отклоняется.
- Снимок старого лобби сохраняется без запуска движка. Чужой снимок недоступен.
- Редактирование документа и переименование не перезаписывают имя либо JSON без явного ввода. Поздний ответ валидации не относится к другому тексту.
- Закрытые данные не появляются в списке, ответе сохранения, стандартном просмотре и справке. Явная правка доступна владельцу.
- Повторный запуск валидного сохранённого конфига повторно проверяет файлы и игру. Лобби не меняется при правках библиотеки.
