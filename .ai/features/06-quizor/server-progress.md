# SDK, ведущий и MCP — ход реализации

Исполнитель: server_integration. Без коммитов; итоговая интеграция и QG у root.

## Выполнено

- SDK: доверенный `ControlRole`, `applyControl`, `presenterView`, `nextWakeAt/wake`,
  `Match.dispatchControl`, запись `seat: -1`/`controlRole`, replay, rollback RNG при отказе.
- Пустые игроковые legalActions не завершают фазу, ожидающую ведущего/часы. Симулятор
  вызывает `wake` в ожидающих фазах. BoardProps получил отдельный канал управления.
- Сервер: назначение одного неиграющего ведущего хозяином до партии; политики none/required;
  host/presenter выбираются сервером заново на control, system недоступен из WS.
- Наблюдатель получает обычный view, только назначенный ведущий — presenterView.
  Присутствие выводится из уникальных живых подписчиков и записывается system-событиями.
- ACL файла: владелец либо безопасная ссылка посещённого/своего лобби. В Quizor используются
  только обычные view: полные вопросы/критерии и presenterView не открывают будущий файл.
  Завершённый пошаговый match для ACL восстанавливается из журнала после рестарта.

## Интеграция завершена

- MCP теперь содержит 18 инструментов. `config_probe` проверяет группу примеров,
  `config_resolve` возвращает настройки и provenance. Настоящий Streamable HTTP проверен:
  верный/неверный текст → 300/0 при field.value=300, question.value=200; источники
  наследования совпадают. Target question рисуется в PNG 768 px; неизвестный target
  возвращает понятный `target_not_found`, адресное превью не помечается partial.
- Превью разрешает картинки только на выбранной поверхности; звук/видео не читаются.
  Quizor SVG использует шрифт для читаемого текста, пользовательский SVG-растеризатор не менялся.
- Дополнительные регрессии: настоящий WS отвергает подмену роли; чужой known-id будущего
  файла даёт HTTP 403, текущий открытый файл — 200; finished journal сохраняет ACL после
  рестарта. Выход гостя-ведущего учитывается как активное участие.
- Проверен настоящий Quizor: pause → закрытие процесса → restoreAll без подписчиков →
  онлайн только подключившийся игрок → resume через 3 с с сохранённым остатком времени →
  ответ и 100 очков. Будущий prompt и эталон не попадают в player view.
- Найден и исправлен сценарий late presence: dispatchControl мог завершить игру по
  таймеру и вернуть finished, не обновив lobby.status. Красный тест получил playing вместо
  finished; после явного advance и свежего DTO подписки — зелёный.
- Найден и воспроизведён ACL-обход через ответ `{asset: "ast_будущего_файла"}`:
  общий рекурсивный обход view принимал ownAnswer за доверенное медиа. Красный тест получил
  доступ true. Исправление — `games/media-refs.ts`: белый список blocks/preload/fields/reveal
  и history.{blocks,fields,reveal}, без ownAnswer/answers. ACL и PNG используют общий helper.
