# Технические решения

Решения приняты агентом 2026-11-12 в разрешённом автономном режиме. Продукт P00–P42
остаётся источником требований; объём не сокращается.

## Исходная система

Прочитаны карточки sdk, games, server, assets, mcp, web, dev-env и соответствующий код.
`GameDefinition` содержит чистые setup/applyAction/view и схемы Zod 4; `Match` журналирует
действия и восстанавливает пошаговые игры. Он сейчас допускает действия только мест
0…N−1 и умеет один таймер хода. Русское поле уже прячет правила через presentRules.
LobbyMember.role — строка, на сервере сейчас player/spectator. Комнаты сериализуют
действия замком. DTO лобби общий, view партии индивидуален. Медиа сейчас только картинки:
Asset хранит mime/bytes/path/width/height; Fastify читает загрузку целиком в Buffer до 2 МБ.
Превью — статический SVG React-компонента через resvg. MCP инструменты используют общий
каталог и не выполняют игровых действий. Пакеты публикуют исходники TS.

## T01. Модель и наследование

- Варианты: новая игра со своим автоматом; раздувание общего движка механиками квиза.
- Рекомендация и решение: `games/quizor`, version 1, строгие схемы, один раунд SDK.
  Последовательные/табличные раунды, финалы, судейство и очки живут внутри Quizor.
  Общие настройки разрешаются quiz → round → question → field; вложенные объекты
  сливаются по ключам, массивы заменяются. Пробник возвращает значения и источники.
  Никакого исполняемого кода из конфига. До 500 вопросов, JSON до 2 МиБ.

## T02. Ведущий и доверенные действия

- Варианты: ведущий занимает фиктивное игровое место; отдельная роль и канал управления.
- Решение: роль `presenter` в LobbyMember, назначение хозяином только вне активной партии.
  Ведущий не входит в seatUsers. SDK получает необязательные applyControl/presenterView,
  dispatchControl с ролью host/presenter/system и журналированием. Сервер сам определяет
  роль на каждом действии; клиент не передаёт доверенный actor. Обычный applyAction
  никогда не даёт прав ведущего. System используется только сервером для присутствия.

## T03. Часы и восстановление

- Варианты: realtime с тиками; пошаговый автомат с ближайшим событием.
- Решение: необязательные nextWakeAt/wake в GameDefinition и Match, чтобы будить игру
  на смену блока, закрытие, торги, апелляцию и раскрытие. Все времена — часы сервера.
  Пауза замораживает дедлайны, возобновление с отсчётом 3 секунды; событие сохраняется
  в журнале. Невалидные действия не двигают RNG. Присутствие учитывается сервером.

## T04. Тайна

- Решение: presentRules отдаёт только сводку. view — белый список: текущие открытые блоки,
  доступные поля без критериев, отметки ответивших, свой ответ; чужие ответы и очки
  текущего вопроса только при раскрытии. Presenter получает отдельный доверенный view.
  Права на файлы для Quizor проверяются по уже открытым ссылкам view; знание id будущего
  файла не открывает его участнику. Владелец файла сохраняет доступ к своему пулу.

## T05. Медиа

- Варианты: хранить ссылки/чужие плееры; расширить существующий пул.
- Решение: свой пул, потоковая загрузка на диск с ограничением размера, сигнатуры WAV,
  MP3, OGG, M4A/MP4, WebM. Картинки сохраняют прежние лимиты. Один медиафайл до 1 ГиБ,
  уникальные медиа квиза суммарно до 1 ГиБ, пул пользователя до 10 ГиБ. Range/HEAD
  для перемотки без чтения файла целиком. Импорт сохраняет защиту SSRF. Без перекодирования:
  агенту сообщаются поддерживаемые контейнеры и браузерные ограничения кодеков.

## T06. Проверка и авторинг

- Решение: отдельный чистый модуль проверки с объяснением оценки. Типизированные ступени,
  приоритет явно неверного текста, Damerau–Levenshtein по словам, числовые/плоские расстояния,
  составные поля и настраиваемые оценки. MCP config_probe, config_resolve и адресное
  config_preview для вопроса/табло/заставки; ИИ-судья отклоняется понятной диагностикой.
  Шесть пресетов и руководство с рецептами. Симуляции остаются тестовым инструментом,
  MCP не ходит за игроков.

## T07. Сцена

- Решение: React HTML-доска с внутренней прокруткой, верхней строкой раунда,
  центральной сценой и нижней полосой участников. Формы всех полей доступны мышью,
  клавиатурой и касанием. Fullscreen через BoardProps.fullscreen; compact/mute локально.
  CSS-анимации появления/счёта, reduced-motion, темы и палитра. StaticRender — SVG
  с векторными элементами и системным шрифтом в доверенном серверном превью.
  Растеризация пользовательского SVG по-прежнему не загружает системные шрифты.

## T08. Персональные часы, круг адресатов и конечный запас

- Решение root в автономном режиме, 2026-11-12: при `pacing:self` «Поторопить»
  ограничивает личные дедлайны оставшихся, а ведущий продлевает или останавливает
  именно личные часы незавершённых ответов. Пауза сдвигает эти часы вместе с остальными;
  игрок видит свой дедлайн, общий экран и ведущий — ближайший из оставшихся.
- `recipient:turn` и `mode:turns` используют отдельный круг мест. Он начинает раунд
  с firstSeat и продвигается после каждого вопроса, пропуская выбывших. Выбор владельца
  хода fastest/trailing и передача ownership не меняют этот круг.
- Запас вопросов конечен, автоматических повторов нет. При исчерпании race/survival
  раунд завершается по общим очкам. В дуэли, если никто не дошёл до K, выигрывает
  набравший больше верных ответов в дуэли: он получает bonus, а при directWinner —
  победу в партии. При равенстве верных работают итоговый счёт и обычный тай-брейк.
  Если K больше запаса вопросов, `checkRules` выдаёт предупреждение с этим объяснением.
